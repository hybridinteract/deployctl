1 Prepare the server

A fresh Ubuntu server, reachable as root with your ssh key. One script, run once as root, does the rest: Docker, the {{ bootstrap.ssh_user }} user with your keys, the deploy directory, swap, and key-only ssh.

From this machine, once per new server:

{% for h in bootstrap.hosts %} {{ codeblock('boot-cmd-' ~ loop.index, "deployctl server bootstrap-script --env " ~ env ~ " | ssh root@" ~ h ~ " 'bash -s'") }} {% endfor %}

For a new server. It upgrades packages and reboots at the end when the kernel changed. On a server that already serves traffic add --no-reboot after bootstrap-script — or leave it alone: a server deployctl already deploys to has everything this script sets up.

Then check that the deploy user can reach Docker:

{{ codeblock('boot-check', "ssh " ~ bootstrap.ssh_user ~ "@" ~ bootstrap.hosts[0] ~ " docker ps") }}
▶ Read the script {{ codeblock('boot-script', bootstrap.script) }}
    {% if bootstrap.tls_le %}
  • DNS: an A record for {{ bootstrap.domain or 'your domain' }} → the server's public IP, before the SSL step. Ports 80 and 443 open; certbot needs 80.
    • {% elif bootstrap.tls_lb %}
  • DNS: an A record for {{ bootstrap.domain or 'your domain' }} → the load balancer, not a host. Every host in both databases' trusted sources.
    • {% endif %}
  • Port 22 must accept CI as well as you: open with keys only, or a tailnet or jump host — see the CI/CD tab.
